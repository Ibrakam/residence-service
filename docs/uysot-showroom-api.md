# Uysot Showroom — карта данных для лендинга Avalon Residence

Дата аудита: 2026-08-23  
Исходный интерфейс: `https://app.uysot.uz/showroom/`  
API origin: `https://service.app.uysot.uz`  
Медиа origin: `https://src.service.app.uysot.uz` и `https://src.srv.showroom.app.uysot.uz`

## Главное

- В CRM изучены все четыре режима showroom: список, шахматка, расширенная шахматка и визуальный вид.
- Для проекта используется `houseId = 1074`, для компании — `companyId = 504`.
- В каталоге 268 объектов: `B1` — 80, `A` — 108, `B2` — 80.
- В проекте сейчас встречаются 2- и 3-комнатные объекты.
- Для лендинга нужен серверный read-only адаптер. Пароль и токен нельзя размещать в браузерном JavaScript.
- Разрешён только HTTP `GET`. Любые `POST`, `PUT`, `PATCH`, `DELETE` должны блокироваться в коде адаптера.
- Переданные логин/пароль намеренно не сохранены в репозитории.

## Изученные маршруты интерфейса

| Маршрут | Назначение | Что показывает |
|---|---|---|
| `/showroom` | Табличный каталог | ЖК, корпус, квартира, этаж, комнаты, площадь, цены, ремонт, статус |
| `/showroom/shaxmatka` | Компактная шахматка | Корпуса/подъезды, этажи, номера и статусы, карточка выбранной квартиры |
| `/showroom/shaxmatka-plus` | Расширенная шахматка | Номер, комнатность, площадь, цена и цена за м² прямо в ячейке |
| `/showroom/visual/` | Визуальный вид | Фасад с хотспотами, карточка квартиры, планы 2D/3D, погодный фон |

Визуальный режим предлагает фоны `Солнечно`, `Дождливо`, `Снежно`. Для текущего фасада автопроигрывание отключено, так как наблюдался один активный медиаресурс.

### Статусы CRM

В фильтре CRM отображаются:

- `В продаже`
- `Занятый`
- `Распроданный`
- `Резерв`
- `Ключи переданы`
- `Оформлено на клиента`

В шахматке легенда отображает:

- `Свободно`
- `Занято`
- `Продано`
- `Не продается`
- `Ключ передан`
- `Оформлено на клиента`

Названия в фильтре и легенде различаются. В лендинге следует нормализовать их в собственный enum, но хранить исходное значение CRM рядом для диагностики.

## GET API, необходимые лендингу

Все URL ниже были фактически замечены при работе интерфейса. Дополнительно выполнены прямые `GET`: сервер принимает маршрут и отвечает JSON-конвертом, а не `405 Method Not Allowed`.

### 1. Справочник ЖК

```http
GET https://service.app.uysot.uz/v1/smart-catalog/house
```

Назначение: доступные ЖК и базовые метаданные. Для Avalon нужно выбирать запись с `id = 1074`.

### 2. Корпуса/здания ЖК

```http
GET https://service.app.uysot.uz/v1/smart-catalog/building/1074
```

Назначение: корпуса `B1`, `A`, `B2` и их внутренние идентификаторы. Нельзя связывать данные только по отображаемому имени — в фильтрах следует использовать внутренний ID из ответа.

### 3. Диапазоны и варианты фильтров

```http
GET https://service.app.uysot.uz/v1/smart-catalog/filter-properties/1074
```

Назначение: доступные комнатности, диапазоны этажей/площади/цен и прочие свойства для фильтра каталога.

### 4. Данные шахматки

```http
GET https://service.app.uysot.uz/v1/smart-catalog/showroom?realtorBookingCount=false
```

Также наблюдался вариант без query-параметра:

```http
GET https://service.app.uysot.uz/v1/smart-catalog/showroom
```

Назначение: полный набор объектов, сгруппированный для шахматки. Это основной кандидат для этажей, позиций, номеров, статусов, площадей и цен.

### 5. Табличный каталог

```http
GET https://service.app.uysot.uz/v1/smart-catalog/table
```

Назначение: список объектов для карточек и каталога. В CRM из него формируется таблица со следующими колонками:

- название ЖК;
- корпус;
- номер квартиры;
- этаж;
- количество комнат;
- площадь;
- цена за 1 м² без ремонта;
- цена за 1 м² с ремонтом;
- стоимость без ремонта;
- стоимость с ремонтом;
- состояние ремонта;
- статус договора.

### 6. Карточка конкретной квартиры

```http
GET https://service.app.uysot.uz/v1/smart-catalog/flat/{flatId}
```

Пример наблюдаемого соответствия:

```text
flatId: 483372
номер: 70
корпус: B1
этаж: 11
комнат: 2
площадь: 55.3 м²
цена: 812 910 000 UZS
цена за м²: 14 700 000 UZS
статус: Свободно
```

`flatId` и номер квартиры — разные поля. Ссылки и запросы деталей должны строиться по `flatId`, а номер использоваться только для отображения.

### 7. Статистика блоков для сайта/визуального режима

```http
GET https://service.app.uysot.uz/v2/website/block-statistic/1074
```

Назначение: агрегаты блоков/статусов, используемые визуальным видом и пригодные для счётчиков на лендинге.

### 8. Дополнительные данные карточки

Эти GET наблюдались после открытия расширенной информации квартиры:

```http
GET https://service.app.uysot.uz/v1/flat/more?flats={flatId}
GET https://service.app.uysot.uz/v1/shourum/flat-data?flatIds={flatId}
GET https://service.app.uysot.uz/v1/flat/field
GET https://service.app.uysot.uz/v1/currency/504
```

Важно: `shourum` в URL написано именно так на стороне Uysot. Не исправлять на `showroom`.

Эти запросы не нужны для первого релиза, если `/smart-catalog/flat/{flatId}` уже содержит карточку, планы и текущую цену. Их следует подключать только при отсутствии нужных полей в основном ответе.

## Медиа

Планы квартир и этажей отдаются обычными GET-файлами:

```text
https://src.service.app.uysot.uz/files/com-{companyId}/thumbnail/{file}
https://src.service.app.uysot.uz/files/com-{companyId}/image/{file}
```

Наблюдаемые файлы для квартиры №70:

```text
https://src.service.app.uysot.uz/files/com-504/thumbnail/260603-165708-0772cab7-201a-4512.png
https://src.service.app.uysot.uz/files/com-504/image/260603-165708-0772cab7-201a-4512.png
https://src.service.app.uysot.uz/files/com-504/image/260603-165712-ccad1856-67fe-4dbb.png
```

Первый полноразмерный PNG — план выбранной квартиры, второй — план этажа с соседними квартирами. Оба файла имеют размер 4961×3508.

Фасад визуального режима отдаётся публичным showroom-сервисом:

```text
https://src.srv.showroom.app.uysot.uz/v1/public/files/image/{file}.jpg
```

Наблюдаемый фасад Avalon Residence:

```text
https://src.srv.showroom.app.uysot.uz/v1/public/files/image/260603-121622-2c726198-b201-4884.jpg
```

Размер: 1920×1080.

Медиа-URL нужно брать из API-ответа, а не фиксировать в коде: имена файлов могут измениться после обновления планировок в CRM.

## Что не включать в лендинг

В интерфейсе также загружаются служебные CRM-запросы (`account`, задачи, новости, Featurebase, Formbricks, Sentry, websocket и другие). Они не относятся к каталогу недвижимости и не должны попадать в интеграцию лендинга.

Не включать в read-only клиент:

- расчёт скидок и предоплат;
- бронирование;
- создание заявок/лидов;
- печать коммерческого предложения;
- внутренние таблицы CRM;
- websocket CRM;
- любые запросы с методами кроме `GET`.

## Авторизация: важное ограничение

Текущая браузерная сессия уже была авторизована под showroom-пользователем, поэтому интерфейс и данные удалось изучить без повторной передачи пароля.

Проверено:

1. `GET` с HTTP Basic Auth и переданными логином/паролем возвращает HTTP 200, но тело `{ "status": -1, "error": null, "data": null }`.
2. Передача тех же данных как заголовков `Login`/`parol` возвращает HTTP 401 `Access denied`.

Следствие: логин/пароль не являются готовыми Basic API credentials. Веб-приложение использует авторизованную сессию/токен, полученный своим процессом входа. Так как для лендинга разрешены только GET-запросы, нельзя строить синхронизацию на POST-логине при каждом запуске.

Перед реализацией production-синхронизации нужен один из вариантов:

1. предпочтительно — отдельный долгоживущий read-only API token от Uysot;
2. публичный GET showroom feed, включённый Uysot для `houseId = 1074`;
3. серверный секрет, который выдаётся/обновляется вне runtime лендинга и используется только серверным прокси.

Нельзя:

- класть логин, пароль или Bearer token в frontend bundle;
- отправлять токен клиенту через HTML/JSON;
- хранить секреты в Git;
- обращаться с браузера напрямую к CRM при отсутствии специально разрешённого CORS и публичного read-only токена.

## Рекомендуемая архитектура

```text
Uysot GET API
      ↓
server-only adapter / cache
      ↓
нормализованный API лендинга
      ↓
каталог / фильтры / шахматка / карточка / визуальный вид
```

Серверный адаптер должен:

- иметь жёсткий allowlist хостов и путей из `uysot-showroom-api.json`;
- разрешать только `GET`;
- отклонять URL с неизвестным origin или путём;
- хранить секрет в переменных окружения/secret manager;
- кэшировать каталог 30–60 секунд, детали квартиры 30–60 секунд, медиа по их cache headers;
- при ошибке Uysot показывать последний успешный snapshot с отметкой времени;
- не менять статус квартиры локально, а всегда считать CRM источником истины;
- логировать только endpoint, status code, latency и request ID — без Authorization header и персональных данных.

## Нормализованная модель для лендинга

Минимальная модель квартиры:

```ts
type Apartment = {
  id: number;                 // внутренний flatId Uysot
  houseId: number;            // 1074
  buildingId: number | string;
  buildingName: "B1" | "A" | "B2" | string;
  number: string;
  floor: number;
  rooms: number;
  areaM2: number;
  propertyType: "residential" | "commercial" | string;
  repairState: "with_repair" | "without_repair" | string;
  status: "available" | "occupied" | "sold" | "reserved" | "not_for_sale" | "keys_transferred" | "registered_to_client" | string;
  statusRaw: string;
  priceUzs: number | null;
  pricePerM2Uzs: number | null;
  priceWithRepairUzs: number | null;
  pricePerM2WithRepairUzs: number | null;
  plan2dUrl: string | null;
  floorPlanUrl: string | null;
  plan3dUrl: string | null;
  updatedAt: string | null;
};
```

`null` обязателен для цен и медиа: в CRM у занятых/проданных объектов цена иногда отображается как `-`, а 3D-план для проверенной квартиры отсутствовал и заменялся стандартной заглушкой.

## Контрольный набор для тестов

После подключения API автоматический smoke test должен проверять:

- `houseId = 1074` присутствует и называется `AVALON RESIDENCE`;
- корпуса `B1`, `A`, `B2` присутствуют;
- суммарное количество объектов не нулевое;
- каждый объект имеет уникальный `flatId`;
- комбинация `buildingId + number` не дублируется;
- статус принадлежит известному enum или попадает в `unknown` с сохранением `statusRaw`;
- цена и цена за м² либо положительные числа, либо `null`;
- медиа URL используют только разрешённые Uysot origins;
- выборочная квартира №70 в корпусе B1 разрешается в `flatId = 483372` (пока данные CRM не изменены).
